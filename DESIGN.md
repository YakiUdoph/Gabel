# Gabel design standards

Created: 2026-11-02 from the current UI and phase requirements. This file did not guide earlier implementation.

- Preserve a premium, minimal, content-first interface.
- Use plain-language actions and truthful state descriptions.
- Keep one primary action per workflow stage; never automate a post mutation.
- Show the complete intended asset list and sanitized before-state before confirmation.
- Distinguish verified success, failure, and ambiguous outcome without celebratory or misleading copy.
- Use semantic HTML, programmatic labels, native keyboard controls, visible focus, sufficient contrast, responsive tables/content, and appropriate status semantics.
- Use system fonts and CSS only unless a future licensed asset has a demonstrated purpose.
- Do not add decorative dashboards, fake data, testimonials, invented metrics, analytics, marketing trackers, or paid-plan UI.
